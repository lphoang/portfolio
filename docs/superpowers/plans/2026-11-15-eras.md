# Eras Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace light/dark mode with two immersive eras, "1889" (Starry Night) and "terminal" (green), switched by a navbar toggle that flies a craft across the screen and reveals the new era like a curtain.

**Architecture:** A `data-era` attribute on `<html>` (set before paint by the inline script) drives CSS tokens. The existing utility names (`font-display`, `text-muted`, `bg-badge`, …) are remapped per era, and inside cards, so most components don't change. The View Transitions API does the curtain. Two client canvases draw the living backgrounds. The 3D figure gets era outfits, baked into six files.

**Tech Stack:** Next.js 16, React 19, Tailwind CSS 4, React Three Fiber, View Transitions API, Canvas 2D, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-15-eras-design.md` (approved). Reference mockup: `docs/superpowers/specs/2026-11-15-eras/eras-reference.html`, the source of the CSS, canvas and craft code to port.

## Global Constraints

- Era values: `'starry' | 'terminal'`. Storage key `era`. Default `terminal`. The old `theme` key is ignored.
- Era tokens and fonts exactly as the spec's tables. No gold in 1889.
- Transition: `1.6s`, `cubic-bezier(.45,.05,.55,.95)`, the same for the craft and the curtain.
- Reduced motion: no craft, no background motion, no blinking or flicker. Each background shows one still frame.
- Backgrounds animate only in their own era, and only while the tab is visible.
- Every era text pair meets WCAG AA (4.5:1, or 3:1 for text ≥ 24px).
- Figure: six baked files `public/figures/<variant>-<era>.json`, step `0.25`, each under 150 KB gzipped.
- No copied game or brand looks. Keep code plain. No ticket IDs in code.
- Commits: `Feat:`/`Fix:`/`Chore:` style, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `eras`.

## Review Focus

- Double-clicking the toggle during a transition: the second click is ignored, and the craft never gets stuck on screen. Test: Task 3.
- A view transition that fails or is skipped (tab hidden, navigation mid-flight): the era is still applied and the craft is hidden again. Test: Task 3.
- A returning visitor with the old `theme` key (`light`/`dark`) or blocked storage gets the terminal era, with no crash and no flash. Test: Task 1.
- Resizing or rotating the window while a background animates: canvases resize, with no stretched or blank areas. Checked by hand in Task 8.
- Switching eras on a slow connection before the other era's figure file has loaded: the figure keeps the old outfit until the new one arrives, never a blank square. Test: Task 7.
